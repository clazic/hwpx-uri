## 0. 한 줄 요약

이 양식은 **스타일 이름이 곧 보고서 기호 체계(□ ○ - ※)** 이고, 모든 서식이 **95개 스타일 ID에 캡슐화**되어 있다.
따라서 변환기의 본질은 *"입력 텍스트의 계층을 판별해 올바른 `styleIDRef` / `paraPrIDRef` / `charPrIDRef`를 부여"* 하는 것 하나로 수렴한다.
HWPX는 텍스트 노드(`<hp:t>`)에 스타일 ID를 연결하면 폰트·크기·색·정렬·들여쓰기·줄간격·자간을 **자동 적용**하므로, 변환기가 직접 서식 값을 계산할 필요가 없다.

## 2. 폰트 체계 — KoPub 패밀리 중심

`header.xml`은 lang별(HANGUL/LATIN/HANJA/JAPANESE/OTHER/SYMBOL/USER)로 동일한 폰트 테이블을 보유한다. 실제 본문에서 사용되는 핵심 폰트:

| 역할 | 폰트 | 사용처 |
|------|------|--------|
| 본문 명조 | **KoPub바탕체 Light** | 바탕글, ○ 주요항목, - 세부설명, 1) 세부, 제1장, 간지 |
| 강조 명조 | **KoPub바탕체 Bold** | □ 대제목 |
| 본문 고딕 | **KoPub돋움체 Light** | ※ 비고, 표내용, 참고문헌, 주-자료 |
| 강조 고딕 | **KoPub돋움체 Medium** | (1) 상세, 표그림제목, 표머리, 표제목 |
| 굵은 고딕 | **KoPub돋움체 Bold** | 1. 소절(소절 제목), 부록 |
| 보조 | **맑은 고딕** | 표 단위 |

> 변환기는 폰트를 직접 지정하지 않는다. 올바른 스타일 ID만 부여하면 위 폰트가 자동 적용된다.
> 단, **대상 PC에 KoPub 폰트가 없으면** 한글 뷰어가 대체 폰트로 렌더링한다(레이아웃은 유지). 배포 환경 확인 권장.

## 4. 입력(마크다운) → 양식 스타일 변환 규칙

| 마크다운 입력 | → 산출 단락 | 스타일ID | 비고 |
|---|---|:---:|---|
| `# 제목` (H1) | ① 장 간지(`Ⅰ`) + ② 간지 미니목차(표) + ③ 장 제목(`Ⅰ. 제목`) | 20 → (tbl) → 4 | **3개 단락 + 1표 세트** 생성, 로마숫자 자동(Ⅰ Ⅱ Ⅲ…) |
| `## 제목` (H2) | 소절 `1. 제목` | 5 | 장 내 번호 자동 증가 |
| `### 제목` (H3) | 세부항목 `1) 제목` | 6 | |
| `#### 제목` (H4) | 상세항목 `(1) 제목` | 6(=H3와 동일 스타일, 기호만 `(1)`) | |
| 일반 문단 / `- 항목` | 주요항목 `○ 텍스트` | 8 | 보고서 2단계 |
| 들여쓴 `  - 항목` | 세부설명 `- 텍스트` | 9 (p41) | 보고서 3단계 |
| 2단 이상 들여쓴 항목 | 비고 `※ 텍스트` | 26 | 보고서 4단계 |
| `> 인용` 또는 `*비고*` | 비고 `※ 텍스트` | 26 | (정책 결정 필요) |
| 마크다운 표 `\| … \|` | 표제목 + TBL(3행 등) + 자료 | 31 + tbl + 69 | §5 표 생성 규칙 |
| `![캡션](img)` | 그림영역 placeholder + 그림 캡션 | (그림틀) + 12 | 이미지 BinData 삽입은 별도 |
| `## 참고문헌` 섹션 | 참고문헌 제목 + `• 항목` 목록 | 4 + 21 | 본문 끝 |

> **개요 자동번호 미사용**: 모든 본문 paraPr의 `heading type="NONE"`. 즉 "1.", "1)", "(1)" 같은 번호는 **자동 생성이 아니라 텍스트에 직접 써넣는다**. 변환기가 번호 카운터를 직접 관리해야 한다. (참고: `numbering[1]/[2]` 정의는 존재 — `^1. / ^2. / ^3) / ^4) / (^5) / (^6)` — 향후 자동번호 전환 시 활용 가능.)

## 5. 표(TBL) 구조 — 2종

### 5-1. 데이터 표 (본문 3×3) — 가장 빈번

```
rowCnt=3, colCnt=3, width=35417 HWPUNIT(≈ 본문 폭), repeatHeader=1
borderFill(표 전체)=3 : 4면 SOLID 0.12mm #000000

행0 (헤더):  borderFill=9  → 4면 실선 + 배경 #E5E5E5(연회색),  문단 style=39(표_구분항목)/para31
행1~ (내용): borderFill=3  → 테두리만,                         문단 style=44(표_내용본문)/para91
열 너비: 11805 / 11805 / 11807  (균등 3등분)
행 높이: 헤더 2200,  내용 1600
cellMargin: 개별 정의 없음(표 기본 여백 사용)
```

**변환 규칙**: 마크다운 표를 받으면
1. 위에 `[표 N-M] 표제목` 단락(style 31) 생성
2. 헤더행 셀 → borderFill 9 + style 39, 데이터행 셀 → borderFill 3 + style 44
3. colCnt에 맞춰 열 너비 = `35417 / colCnt` 로 균등 분배(또는 비율)
4. 아래에 `자료: 출처(연도).` 단락(style 69) 생성

### 5-2. 장 간지 미니목차 표 (2×1)

```
rowCnt=2, colCnt=1, width=15341
borderFill(표 전체)=3
셀 borderFill=8 : 좌우 NONE(흰), 상하 CIRCLE 0.2mm 흰 → 칸 구분선만 살린 디자인
문단 style=23(간지-소제목)
내용: "1. [소절제목][페이지번호]" / "2. [소절제목][페이지번호]"
```

각 장(`#`) 시작 시 그 장에 속한 소절(`##`) 목록을 자동으로 채운다. 소절 개수에 따라 행 수가 가변.

## 7. section1 — 본문·참고문헌·부록 (반복 패턴)

본문은 **장(章) 단위로 완전히 동일한 블록이 반복**된다. 1개 장의 구성:

```
[간지]      style20  "Ⅰ"                       ← 장 표지(흰글씨 35pt, 우측정렬)
[미니목차]  tbl(s0/p90)  "1.소절…/2.소절…"      ← 그 장의 소절 목록
[장 제목]   style4   "Ⅰ. 챕터 제목"
  [소절]    style5   "1. 소절 제목"
    [세부]  style6   "1) 세부 항목 제목"
      [상세] style6  "(1) 상세 항목 제목"
        [주요] style8  "○ 주요 항목"
          [세부설명] style8/p41  "- 세부 설명"
        [그림] (그림영역) + style0/p69 "[그림 1-1] 제목"
        [표]   style0/p69 "[표 1-1] 제목" + tbl(3x3) + style8/p41 "자료: 출처"
  [소절2] style5 "2. 소절 제목" …
[다음 장] style20 "Ⅱ" …
```

문서 말미:
```
[참고문헌] style4 "참고문헌"
  style8  "• [저자](연도). 『제목』. 발행기관."   (문헌 유형별 4가지 양식)
[부록]    style4 "부록"
  style5  "1. [부록제목]"
  style8  "○ [부록내용]"
```

**그림·표 번호 규칙**: `N-M` (N = 장 번호, M = 장 내 일련번호). 예: 1장 첫 표 = `[표 1-1]`, 2장 첫 그림 = `[그림 2-1]`. 변환기가 장별 카운터를 관리.

## 8. 자동 생성이 필요한 요소 (변환기의 핵심 부가 로직)

1. **로마 숫자 장 번호** Ⅰ Ⅱ Ⅲ Ⅳ … (간지 + 장 제목)
2. **소절/세부/상세 번호** 1. → 1) → (1) (장이 바뀌면 1부터 재시작)
3. **목차**(section0): 장·소절 제목 + 페이지 — 페이지는 한글이 자동 계산하므로, 텍스트만 채우고 페이지 필드는 양식의 탭/필드 구조 유지

5. **표목차 / 그림목차**: 본문에서 수집한 표·그림 캡션
6. **그림·표 일련번호** `N-M`

## 10. 전용 skill 설계 시사점 (다음 단계 입력)

이 분석에서 도출되는 skill 아키텍처의 뼈대:

1. **입력 파서**: md(마크다운 AST) / txt(휴리스틱 계층 추론) / hml(한글 XML→중간표현). 모두 **공통 중간표현(IR)** 으로 정규화 — IR = `{표지메타, 요약4블록, [장→소절→…→문단/표/그림] 트리}`.
2. **계층 매퍼**: IR 노드 → §3 스타일ID 매핑 (이 보고서의 마스터 테이블이 그대로 룩업 테이블).
3. **조립기**: `hwpx_helpers`의 `clone_para`/`replace_section_body`로 section1 본문 생성 → 카운터로 번호·캡션 부여.
4. **메타·목차 채움기**: section0 placeholder 치환 + 목차/표목차/그림목차/간지 미니목차 자동 생성.
5. **후처리·검증**: linesegarray 제거 → repack(mimetype STORED) → fix_namespaces → placeholder 잔여/ZIP 검증.

> 변환 엔진은 기존 `~/Downloads/hwpx/scripts/hwpx_helpers.py`(lxml) 자산을 그대로 확장하는 것이 자연스럽다(신규 의존성 없음, 검증된 linesegarray/namespace 처리 보유). 단 이 양식 고유의 **장-소절 계층 + 표/그림 캡션 + 목차 자동생성**은 전용 모듈로 신설해야 한다.

## 11. 완성본 실측 증보 (2026-06-10 · `완성본_샘플.hwpx`)

### 11-1. 페이지번호 메커니즘 ★ (§9 "표시 구조 없음" 정정)

- 본문 쪽번호는 **바탕쪽(masterpage)이 표시**한다: `masterpage2.xml`(짝수쪽)·`masterpage3.xml`(홀수쪽)에 `autoNum numType="PAGE"` + 장식(rect·pic)이 있고, section1의 secPr 4개 전부가 `masterPage idRef`로 이 둘을 참조한다.
- **장별 리셋**: 각 장 간지 단락(s20/p13 "Ⅰ Ⅱ Ⅲ Ⅳ")의 run 에 `ctrl > newNum num="1" numType="PAGE"` 가 있어 **모든 장이 1쪽부터 다시 시작**한다(완성본 사양 — 4개 장 전부 확인).
- section0(표지·발간사·요약·목차)은 masterpage0/1(장식만, autoNum 없음)을 참조 → **앞부속에는 쪽번호가 찍히지 않는다**.
- 조립기 영향: 간지 앵커를 복제하면 secPr+newNum 이 함께 복제된다. **조립기 기본 동작은 연속 번호** — `layout.pageNumRestartPerChapter=false`(기본)면 2장 이후 간지에서 newNum ctrl 을 제거해 "목차 다음 1장 첫 쪽부터 1·2·3…" 으로 이어진다(`hwpx.RemovePageNumReset`). true 로 두면 완성본 원본처럼 장별 리셋.
- 한계 유지: 목차의 페이지 숫자는 자동 필드가 아니라 **텍스트 더미** — 갱신하려면 한글에서 차례 새로 고침.
